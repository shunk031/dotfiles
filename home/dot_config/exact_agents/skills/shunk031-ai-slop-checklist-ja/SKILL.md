# AI Slop Checklist JA

## 読了時の応答

- この skill を読んだら、`🧾 私は shunk031-ai-slop-checklist-ja を読みました。` と応答する。

## 概要

日本語の文章を、書き換える前に「AI 臭さ」の観点で点検する。
AI 臭さの中心は、記号や絵文字ではなく「書き手の不在」として扱う。

ユーザーの文章をレビューする前に、詳細基準として [checklist.md](references/checklist.md) を読む。

## ワークフロー

1. 文章の目的、読み手、書き手が引き受けるべき立場を文脈から推定する。
2. [checklist.md](references/checklist.md) を読む。
3. `立場 -> 主体 -> 構造 -> 語彙（用語・単位を含む） -> リズム -> 記号` の順に見る。
4. ユーザーが軽い確認だけを求めていない限り、`checklist.md` の 5 軸で採点する。
5. 影響が大きい順に指摘し、最後に具体的な直し方または短い修正案を出す。

### 技術報告の用語監査

技術報告では、文が流暢でも用語と単位が曖昧なら公開前に止める。次を語彙の点検として必ず行う。

- 原文にない短縮語やラベルを、整理のためだけに作らない。読み手が意味を推測するしかない語は、元の意味を保つ平易な日本語に戻すか、最初に定義する。
- 数量詞と単位を切り分け、単位の最初の使用箇所で何を数えるかを明示する。元の文章から数える対象が分からない場合は、勝手に補わず確認する。
- 略語、英語ラベル、処理段階名は、最初に正式な意味と役割を添えるか、読者向けの語に置き換える。
- 用語の定義が入力にない場合、もっともらしい定義を捏造しない。未定義であることを指摘し、ユーザーに確認するか、定義なしでも読める表現に書き換える。

## 出力形式

標準では次の形で返す。

```markdown
## 判定
- 総評: ...
- 書き直し推奨: はい/いいえ
- スコア: ../50

## 重大な順の指摘
- 問題箇所: ...
  理由: ...
  直し方: ...

## チェックリスト
- [ ] 立場
- [ ] 主体
- [ ] 構造
- [ ] 語彙
- [ ] リズム
- [ ] 記号

## 修正案
...
```

短文では圧縮してよいが、`判定`、重要な指摘、`修正案` は残す。

## 注意点

- 体験、数値、固有名詞、失敗、好き嫌い、感情を捏造しない。
- 書き手の立場が足りないときは、書き換える前に不足している材料を示す。
- 事実、意図、必要な丁寧さを保つ。
- 流暢さや箇条書きの整形だけで合格にしない。未知のラベル、略語、単位、数える対象がない数量表現を、重大な指摘として先に挙げる。
- 人間らしく見せるために、わざと雑な文章にしない。
- 表層の特徴に寄せすぎない。ダッシュ、カギ括弧、絵文字、Markdown 残骸は、立場と主体を見たあとで直す。
